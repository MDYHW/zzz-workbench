# Version 2.8 Vertical Expansion Roadmap

> **Recovery suspension:** Automatic vertical continuation is suspended. The
> current runtime roster and completed-milestone entries are unverified audit
> evidence until the authority-governance recovery is accepted and promoted to
> trusted `main`. Grace remains `frozen-by-recovery`; no Anomaly or later
> vertical may start from this roadmap during recovery.

## Purpose

Complete the initial Version-2.8 Agent cohort through small verticals that reuse
the workbench's current setup-to-Result meanings. Version 2.8 bounds which
Agents enter this first cohort; admitted Agents use their current released
behavior. This roadmap sequences work and marks semantic stop gates. It is not
product authority, a content catalogue, or an implementation plan.

Each vertical independently authors current identity, direction, candidate
membership, pool-specific whole-package representatives, retained calculation
facts, Result projection, and visible Setup behavior. External guides are
shortlist and interpretation aids. They do not replace holder eligibility,
consumer, complete-package, opportunity-cost, same-pool, lifecycle, and
contrasting-consumer checks.

## Repeated completion gate

For every vertical:

1. Author the bounded requirement from permanent owners, exact current facts,
   the closest established consumer, and a contrasting consumer.
2. Stop only for a genuine unresolved product meaning; do not ask the user to
   choose a discoverable game fact.
3. Write one active bounded plan after requirements close.
4. Use one mutating worker in the shared checkout and adaptive review effort.
5. Verify shared mechanisms, representative flows, build, diff hygiene, and
   the affected browser journey at `127.0.0.1:5173`.
6. Commit the implementation, record a compact milestone, remove the completed
   plan body after it has been preserved in Git, and continue to the next
   vertical when no semantic gate remains.

This repeated gate describes the post-recovery sequence only. During recovery,
the recovery plan and protected repository policy supersede its continuation
step without changing any product meaning in this roadmap.
