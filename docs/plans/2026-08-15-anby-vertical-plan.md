# Anby Demara Vertical Plan

## Visible Outcome

Users can select Anby Demara as a distinct Agent from Anby: Soldier 0, receive a
complete zero-substat setup in either W-Engine pool, edit every competitive
choice, and inspect retained Stun, action, threshold, and equipment consequences
in Result. Party preparation composes Anby with the existing one-King
King/Astral/Shockstar allocation and preserves the accepted two-Stun tie.

## Assumptions

- Demara Battery Mark II keeps its activation event in compressed Setup copy;
  no calculation or eligibility consumer needs a new generic trigger enum.
- The current deterministic flexible-Stun tie appends Anby after Lycaon. It is a
  prepared-first-choice tie only, not a universal Stun ranking.
- Original portrait evidence may require new Anby metadata, but must not alter
  Anby: Soldier 0 metadata or turn the shared portrait maps into a catalogue.

## Boundaries

- Add no rotation, Energy gauge, Energy Generation Rate stat, Shock state,
  ordinary skill multipliers, raw damage, raw Daze, or runtime optimizer.
- Keep M1, M4, and the Additional Ability Energy event omitted from runtime
  facts and Result. Retain only Demara Battery Mark II's conditional Energy
  Generation Rate in compressed Setup copy, without projecting it as Energy
  Regen or a Result operation.
- Extend existing candidate, selected-pressure, allocation, exact-action, and
  lifecycle mechanisms. Do not add a named-Agent Stun scorer or priority table.
- Preserve incomplete selection, party-wide Apply rebuild, target-only pool or
  Mindscape rebuild, and direct-edit locality.

## Units

1. Add the distinct non-Focus-eligible Anby identity, Cunning Hares faction
   membership, retained values, Demara W-Engine facts and copy, equipment
   pools, Drive Disc and main candidates, representatives, source labels, and portrait wiring. Rename
   Soldier 0-local internal Anby labels only where needed to prevent ambiguity.
2. Add Anby-local calculation and provider participation for ATK, Impact, Energy
   Regen, selected equipment, King threshold, Core Thunderbolt/Special/EX Daze,
   M2 target-state action differences, and M6 Basic/Dash DMG. Assert that
   Additional, M1, M4, and Demara resource clauses do not become Result facts.
3. Extend shared selected-King candidate pressure and the bounded flexible-Stun
   tie. Verify the full authored -> contextual -> selected-derived -> allocation
   -> prepared order, including rigid/flexible, both-flexible, neither-flexible,
   every relevant slot order, and the independent-CRIT Trigger contrast.
4. Integrate selection, state, Setup, and Result through mechanism-oriented
   tests. Cover both pools, zero supplied substats versus the finite nine-hit
   opportunity, selected/removed/reselected King lifecycle, one composed
   direct-edit/pressure-removal/target-rebuild journey, an Anby-containing
   three-Stun draft with no eligible Focus and disabled Apply, incomplete
   Result, and selected/candidate accessible Demara descriptions.
5. Inspect the original portrait and calibrate only evidence-backed Anby source
   metadata. Verify desktop and narrow expanded/compact states at
   `127.0.0.1:5173`, including visible distinction from Anby: Soldier 0, then run
   all tests, TypeScript, production build, and diff checks.
6. Run final correctness, adversarial, maintainability, project-standard, and
   testing review. Resolve supported findings, commit bounded fixes, add the
   completed milestone, and remove this plan only after its committed checkpoint.

## Ownership And Dependencies

The controller owns permanent-authority interpretation, candidates,
representatives, action and Result meaning, preparation order, lifecycle,
portrait calibration, integration, and commits. A worker may own only a settled
mechanical slice with explicit files and must stop on a missing source fact, new
consumer, or unsupported semantic generalization. Identity and content precede
calculation; calculation and preparation precede UI journeys; portrait metadata
requires the fixed-port browser acceptance before closure.

## System-Wide Impact

The vertical follows the existing interaction chain without a new abstraction:
source-owned Agent and equipment facts feed candidate/prepared setup; selected
setup feeds Anby's calculator and party-provider composition; those outputs feed
the shared Setup and Result surfaces. Party allocation mutates only prepared
first choices, while direct setup edits continue to bypass allocation.

## Verification

- Candidate and preparation tests cover exact identity, both W-Engine pools,
  Demara's whole selected/candidate package, base versus selected-King pressure,
  zero-substat representatives, and the preserved Trigger contrast.
- Shared preparation and state flows cover pressure present, absent, and
  reselected; invalid CRIT clearing without fallback; all relevant two-Stun slot
  orders; rigid/flexible, both-flexible, and neither-flexible allocation; and
  target-only reconstruction.
- Calculation tests cover completed base values, Core/M2/M6 exact action scopes,
  Stunned and non-Stunned target distinctions, Demara's broad Electric DMG,
  excluded Energy Generation Rate/resource events, selected Disc/Engine clauses,
  and King's below/above-threshold output.
- UI tests cover distinct Anby identities, accessible selected and candidate
  packages, setup selectors, an Anby-containing three-Stun draft with no
  eligible Focus and disabled Apply, incomplete Result, and no generic resource surface.
- Full repository tests, TypeScript, Vite production build, `git diff --check`,
  original portrait inspection, and in-app Browser desktop/narrow
  expanded/compact checks pass before closure.
