# Add Soldier 11, Lighter, And Lucy Vertical

## Outcome

Users can apply Soldier 11, Lighter, and Lucy, receive deterministic full and
non-limited starting setups, edit bounded competitive choices, and read their
current personal, party, enemy, action, threshold, equipment, and relationship
consequences through the existing Setup-to-Result flow.

## Preserved boundaries and rejected alternatives

- Do not equate Silver Squad with Obol Squad or use a named Agent allowlist.
  Retain exact faction and add only the typed NEDF qualification relation needed
  by Soldier 11's current consumer.
- Do not prepare King on Lighter by inventing CRIT investment at zero. Keep
  Astral as the local representative and add CRIT pressure only when King is
  selected.
- Do not turn Lucy's all-party Core into the existing Focus-only buffer
  mechanism, or her boar inheritance into a personal-damage setup direction.
- Do not add raw damage, rotations, Morale/resource cadence, optimizer,
  historical-version toggle, source registry, evidence payload, named-party
  framework, or per-Agent UI/test suite.
- External research remains ephemeral. Code implements only the settled origin
  requirements and permanent owners.

## Execution posture

- Controller owns semantic authoring, candidate/representative decisions, and
  final integration at frontier/high reasoning.
- Keep one mutating worker at a time in the shared checkout. Route and accept
  each bounded unit independently: use balanced reasoning for mechanical typed
  content and UI-map work, and high reasoning for provider/calculation and
  selected-pressure units. Each dispatch must identify file ownership,
  mutation limits, dependencies, tests/browser work, and unresolved deviations.
- Use balanced medium reviewers for ordinary correctness/testing/standards;
  escalate only a novel/high-risk semantic finding. Never run multiple
  mutating workers in the shared checkout.
