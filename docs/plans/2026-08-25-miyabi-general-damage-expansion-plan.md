# Miyabi Bounded General-Damage Expansion Plan

## Outcome

Deliver one complete prepared Miyabi setup in each availability pool and a
source-linked Result that classifies her direct Frost output as
`general_damage`, preserves only her current `anomaly_buildup` interactions,
and reuses the existing preparation, equipment, provider, action, and visual
systems. Anton and Rina remain outside this plan.

## Settled Boundary

- `GV-004`, `FM-002`, and `FM-007` own Frost-to-Ice calculation and the
  Specialty-independent formula split.
- `SF-001`-`SF-004` retain only current consumer-backed maxima and
  relationships. No Frost state engine or source-completeness schema is added.
- `SW-004`, `SW-005`, `SW-008`, and `SW-009` own the candidate and prepared
  package decisions recorded in the requirement.
- `SW-012`-`SW-015` own delivery, visible projection, compatible fully enabled
  outcomes, and lifecycle.
- `UI-001` owns compressed source Setup copy; `UI-002`-`UI-004` own visible
  Result and portrait behavior.

## Units

### 1. Admission and setup policy

- Add Miyabi to typed identity, Attribute, faction, Focus, formula
  participation, candidate, main-stat, substat, representative, operating
  interval, portrait, and UI identity registries.
- Preserve Frost as the visible identity and map only calculation/applicability
  to Ice.
- Acceptance: full prepares Hailstorm/Branch/Polar/CRIT Rate/Ice DMG/ATK%;
  non-limited substitutes Fusion; all supplied substat counts begin at zero.

### 2. Minimal shared equipment relationships

- Replace Hailstorm's unused two-stack representation with its fully enabled
  direct Ice DMG value and add its selected CRIT DMG and Ice DMG projection.
- Add Branch's AM-threshold CRIT DMG and fully enabled CRIT Rate facts, Setup
  copy, threshold relationship, and selected projection.
- Inspect selected and candidate accessible descriptions against the shared
  facts. Confirm every admitted partial W-Engine keeps whole-package Setup copy
  while Result filters unusable AP, Attribute, action, Specialty, and interval
  clauses.
- Acceptance: no new duration, cadence, stack-acquisition, trigger-runtime, or
  item catalogue structure/test.

### 3. Miyabi source profile

- Extend the current general-damage source profile with Miyabi's base stats,
  qualified local outcomes, action scopes, Frostburn operation, CRIT-derived
  buildup gauge, Mindscape relationships, and shared equipment projection.
- Deliver Frostburn and post-removal buildup only to current
  `anomaly_buildup` recipients using separate action identities. Add matching
  action projections to current recipient profile builders without a second
  calculation pass or state registry.
- Acceptance: ordinary damage modifiers never appear as Anomaly DMG Bonus;
  no AP or `anomaly_damage` metric is admitted; Icefire and Frostburn are not
  summed into a universal buildup row.

### 4. Lifecycle and visible verification

- Exercise Party Apply, Miyabi-only pool/Mindscape rebuild, direct edits,
  broad pre-PEN pressure present/absent/reselected, invalid clearing without
  fallback, zero supplied counts, and incomplete Result through the existing
  shared mechanisms.
- Inspect expanded/compact Setup and Result at desktop and narrow widths with
  Miyabi selected. Calibrate portrait `scale`, `headTopY`, then `faceX`, and
  check selected/candidate equipment descriptions and source highlighting.
- Preserve one pressure-unaffected holder and the current three-holder setup.

### 5. Testing and closure

- Extend the existing special-Attribute mapping table for Frost-to-Ice and
  update only exhaustive registries/shared journeys made incomplete by Miyabi.
- Run focused behavior tests, root tests, TypeScript, production build,
  governance tests, `git diff --check`, and the visual baseline policy.
- Review the final diff against the requirement's Authority decision map and
  complete the plan lifecycle: checkpoint this active plan, add one compact
  milestone to `docs/plans/README.md`, and delete this plan in a follow-up
  commit.

## Testing Delta

- New relationship: Frost is a visible special Attribute whose calculation
  applicability is Ice. Nearest test: the existing table-driven Auric Ink and
  Honed Edge mapping assertion. Missing failure: a new special Attribute could
  display correctly while selected Ice equipment and modifier delivery fail.
  Equivalent-fixture meaning survives; extend that table rather than adding a
  Miyabi suite.
- Reused relationships: post-delivery stat/modifier gauge, action-scoped party
  provider, provider recipient filtering, operating interval, preparation,
  pressure, reconciliation, and incomplete Result. Existing shared fixtures
  already fail on their mechanism defects, so no new test is planned solely
  for Miyabi values, candidates, representatives, or equipment maxima.
- Visual delta: new portrait metadata and identity mark require browser and
  visual-baseline verification. Formula/content-only rows do not create a new
  layout baseline.

## Non-Goals

- No Anton/Rina work, permanent-authority change, runtime Frost state, final
  damage, anomaly history, rotation, uptime, or resource simulation.
- No new shared abstraction unless implementation exposes a current failure
  that the settled relationships cannot express.
- No staging, commit, push, PR, or merge outside the protected governance
  sequence.
