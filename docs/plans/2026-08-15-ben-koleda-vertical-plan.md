# Ben And Koleda Vertical Plan

## Visible Outcome

Users can select Ben or Koleda, receive a complete pool-specific setup, edit all
competitive inputs, and inspect their retained personal and party Result. Ben's
Result includes the one dedicated Core shield amount owned by the requirements;
Koleda composes with the existing King/Astral/Shockstar allocation.

## Boundaries

- Keep Ben's shield as one source-local calculation and Result operation. Do
  not add a survival schema, incoming-damage state, uptime, or shield catalogue.
- Keep Big Cylinder, Spring Embrace, event Energy, and damage reduction in
  compressed Setup packages when the Result gate excludes them.
- Extend current candidate, pressure, exact-identity, preparation, and provider
  mechanisms. Do not add a named-Agent allocation framework or runtime scorer.
- Preserve incomplete selection, party rebuild, target-only rebuild, and direct
  edit behavior.

## Units

1. Add source-owned identities, factions, retained values, W-Engine facts,
   equipment choices, candidates, mains, substats, representatives, and portrait
   wiring. Cover complete selected and candidate descriptions, including
   off-Specialty inactive passives.
2. Add Agent-local Ben and Koleda calculators and provider clauses. Reuse the
   existing stat/action/result structures, adding only DEF, Shield Effect, and
   the bounded shield operation fields required by the visible consumer.
3. Extend candidate and preparation mechanisms for Ben's contextual and broad
   pre-PEN lifecycle plus Koleda's selected-King pressure and bounded two-Stun
   tie. Verify authored, contextual, selected-derived, allocation, and prepared
   order in shared flows.
4. Integrate selection, state, Setup, and Result behavior using the existing
   mechanism-oriented suites. Add cross-vertical contrasts for Big Cylinder,
   Pulchra Proto, Lycaon M4, action-scoped DEF Ignore, single-Stun allocation,
   and neither-Astral fallback.
5. Inspect original portraits, calibrate only source metadata that visual
   evidence requires, then verify desktop and narrow expanded/compact states at
   `127.0.0.1:5173`. Run all tests, TypeScript build, production build, and diff
   checks.
6. Run final correctness, adversarial, maintainability, project-standard, and
   testing review. Resolve supported findings, commit bounded fixes, add the
   completed milestone, and remove this plan only after its committed checkpoint.

## Ownership And Dependencies

The controller owns permanent-authority edits, candidates, representatives,
formula and Result meaning, preparation order, lifecycle, visual calibration,
integration, and commits. A worker may own only a settled mechanical content
slice with explicit files and must stop on any missing source fact or new
consumer. Content precedes calculation; calculation and provider projection
precede UI journeys; portrait changes require browser acceptance.

## Verification

- Candidate and state tests cover both pools, inactive passive copy, exact
  identity, broad pre-PEN on/off/reselected, selected King on/off/reselected,
  and invalid-selection clearing without fallback.
- Preparation tests cover both zero-substat representatives, one composed
  Ben/Koleda flow, every relevant two-Stun slot order, rigid/flexible and
  neither-flexible contrasts, and target-only reconstruction.
- Calculation tests cover Initial DEF to Combat ATK, additive Shield Effect,
  the exact shield equation, qualified provider delivery, action scopes,
  excluded event clauses, and no generic shield output on contrasts.
- UI tests cover selection, accessible selected/candidate packages, incomplete
  Result, and the source-local shield operation.
- Full repository tests, TypeScript, Vite build, `git diff --check`, original
  portrait inspection, and in-app Browser desktop/narrow expanded/compact pass.
