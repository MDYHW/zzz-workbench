# Ship the bounded gear companion

Meaning is settled by merged PR #230 (`SW-016`, `SW-022`, `UI-005`) and the
accepted public-release requirement. The user-approved prototype supplies the
interaction baseline, not a second source of calculation or candidate meaning.

## Units

- U1: Move the working collector, popup and adapter into maintained companion
  source; reuse current candidate and shortcut consumers. Preserve the compact
  popup, explicit choices, same-effect mapping and completion emphasis. Use
  synthetic equipment fixtures instead of the owner's account capture.
- U2: Generate a deterministic minimal ZIP alongside the site; inspect every
  archive entry under the existing public-artifact gate. Exclude source hashes,
  account fixtures, source maps and development files. Keep the existing exact
  release decision and publisher boundaries.
- U3: Retain the HoYoLAB header shortcut and add subordinate, collapsible
  bilingual download/install/use help. Verify desktop and narrow layouts,
  keyboard dismissal, download wiring and the extension's ready/error states.

No new Agent, candidate, calculation, local-URL support, persistent state,
authenticated API access, automatic installation or browser-store submission.

## Testing delta

- U1: Existing shortcut tests validate accepted Setup state, but cannot prove
  visible equipment translation, exclusion disclosure or clearing a stale URL
  after a failed collection/edit. Migrate mechanism tests using synthetic
  fixtures; assertions must survive equivalent Agent/equipment substitutions.
- U2: Existing artifact tests cannot inspect ZIP payloads or reject broadened
  extension permissions. Test canonical archive structure, corrupt/traversal/
  extra entries, forbidden nested content and the exact manifest boundary.
- U3: Existing header and language tests cannot prove opening/dismissing the new
  help and its downloadable file. Add one observable help flow plus browser
  geometry checks for header collision, narrow-panel containment and keyboard
  dismissal; portrait snapshots cannot establish these new control boundaries.
  Reuse the existing full Linux visual baseline suite.

## Completion

Run repository/governance, companion behavior, app behavior, type/build and
Linux visual checks. Review one final implementation PR independently at its
exact head. After owner approval and merge, build/review the exact public tree,
obtain its publication decision, publish through the existing publisher and
verify served bytes and user entry flow. Remove this completed plan and retain
only a milestone after its implementation is merged.
