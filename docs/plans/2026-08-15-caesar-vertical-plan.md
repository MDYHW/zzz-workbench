# Caesar King Vertical Plan

## Visible Outcome

Users can select Caesar King, receive a complete zero-substat setup in either
W-Engine pool, edit every competitive choice, and inspect the exact split
between Initial shield-bearing Impact and post-trigger Fully Enabled Impact.
Result shows Caesar's one shield output, Focus-routed ATK, qualified enemy DMG
Taken, retained action differences, and complete selected equipment packages
without adding a survival or runtime Assist simulator.

## Assumptions

- Caesar's source-local "base Impact" maps to the permanent Initial Stat
  surface. Post-trigger Impact changes Fully Enabled Daze only.
- The current Caesar-only Evasive-Assist exception list is sufficient for the
  admitted roster and is revisited when a later Agent changes qualification.
- Demara Battery Mark II remains an A-Rank accessibility candidate despite its
  inactive passive; Hellfire remains the stronger same-axis representative.
- Original portrait evidence may require Caesar-only source metadata.

## Boundaries

- Add no generic shield, survival, incoming-damage, Assist-type, Energy,
  anomaly, uptime, or rotation model.
- Keep shield depletion, duration, anti-interrupt, one-hit protection, M4
  resource substitution, and ordinary raw action values outside runtime facts.
- Keep DMG Taken distinct from DMG Bonus and use it only for current general-
  and sheer-damage consumers.
- Preserve incomplete selection, party-wide Apply rebuild, target-only pool or
  Mindscape rebuild, direct-edit locality, and existing Stun allocation.

## Units

1. Amend the permanent formula and source-fact owners for Caesar's narrowly
   admitted DMG Taken contribution and dedicated shield relationship; add the
   Caesar identity, retained values, source labels, portrait wiring, setup
   formula participation, candidates, representatives, and Original
   Transmorpher facts/copy. Mark relevant W-Engine passive Specialties so
   selected and candidate Setup can expose inactive clauses accurately.
2. Extend preparation with Caesar's repeated-Quick-Assist Astral candidate and
   present/absent/reselected lifecycle. Preserve the two-layer dependency:
   equipment/Disc context and allocation first, then selected-package-derived
   mains/substats. Verify Caesar adds no King-holder allocation pass.
3. Add Caesar's local qualification helper, calculation context, provider
   clauses, and Result module. Project Initial/Combat versus Fully Impact,
   Shield Effect and the Radiant Aegis operation, M0/M2 Focus ATK, qualified
   DMG Taken, M1 RES Reduction, skill-tier Daze/Impact, M6 capped action CRIT,
   DMG, and primary-target operation, and selected equipment effects.
4. Add one shared enemy-context DMG Taken projection to eligible current
   results without changing their local action or other enemy-metric ownership.
   Cover general, sheer, and excluded non-damage contrasts plus active/inactive
   Additional routes.
5. Integrate selection, state, Setup, and Result through mechanism-oriented
   tests. Cover both W-Engine pools, zero substats, Original/Demara/Hellfire
   active-versus-inactive packages, contextual Astral lifecycle, an unaffected
   Focus/Caesar/Stun allocation, target-only rebuild, incomplete Result, and
   accessible selected/candidate package descriptions.
6. Inspect the original portrait and calibrate only evidence-backed Caesar
   metadata. Verify desktop and narrow expanded/compact states at
   `127.0.0.1:5173`, then run all tests, TypeScript, production build, and diff
   checks.
7. Run final correctness, adversarial, maintainability, project-standard, and
   testing review. Resolve supported findings, commit the bounded vertical,
   add the completed milestone, and remove this plan only after its committed
   checkpoint.

## Ownership And Dependencies

The controller owns permanent-authority changes, candidates, representatives,
formula/recipient/action meaning, preparation order, lifecycle, portrait
calibration, integration, and commits. Mechanical implementation may follow
only after the exact consumers above are fixed. Identity/content precede
calculation; calculation and preparation precede UI journeys; portrait metadata
requires fixed-port Browser acceptance before closure.

## System-Wide Impact

The vertical extends the existing interaction chain: source-owned Agent and
equipment facts feed candidate/prepared setup; selected setup feeds Caesar's
calculator and party-provider composition; one new enemy metric is projected
through the shared Result boundary only after formula eligibility has filtered
the source. The shield stays a Caesar-owned operation, Focus ATK stays a normal
recipient clause, and direct edits never rerun allocation.

- Full repository tests, TypeScript, Vite production build, `git diff --check`,
