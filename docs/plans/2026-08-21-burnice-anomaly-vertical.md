# Burnice Anomaly Vertical Implementation Plan

## Outcome

Deliver one complete Burnice setup per availability pool and make her Initial
Energy Regen/AP relationships, equipment, action modifiers, provider effects,
Mindscape operations, and lifecycle visible through the existing Setup and
Result surfaces defined by the approved Burnice requirement.

## Execution Units

1. Add Burnice identity, retained source values, portraits, W-Engine facts and
   summaries, candidate membership, independent Disc roles, mains, substats,
   and pool representatives.
2. Add Burnice observation, provider clauses, Agent-local calculation, action
   hierarchy, gauges, and complete operations; connect dispatch and existing
   shared Attribute Anomaly/Disorder composition without adding a new generic
   framework.
3. Extend shared content, calculation-flow, lifecycle, and UI coverage only for
   materially distinct behavior: the two-output Potential gauge, fixed `/s`
   separation, exact operations/scopes, selected/candidate copy parity, and one
   composed pressure/completeness flow.
4. Run focused verification continuously, then the full Vitest suite, type
   check, production build, and `git diff --check`.
5. Inspect original portrait/art assets and verify Burnice at
   `127.0.0.1:5173` at desktop and narrow widths, expanded and compact.
6. Review the complete diff, checkpoint the plan in Git history, replace this
   plan with one compact completed milestone, and complete the protected PR
   transaction through exact-head independent review, evidence, checks, and
   the owner-approval boundary.

## Ownership And Dependencies

- The approved Burnice requirement owns local product outcomes.
- The five permanent owners and current shared consumers own formula,
  preparation, lifecycle, Setup, Result, and UI meaning.
- Controller owns semantic integration and external transactions. A single
  bounded worker may own settled content files; it must stop on any new shared
  mechanism or product decision.

## Non-Goals

- No final damage, anomaly history/share, Heat, Abloom, rotation, cadence,
  uptime, or runtime optimization.
- No Anton/Rina, later cohort Agent, new permanent authority, or reusable
  reaction framework in this transaction.
- No exact local candidate roster snapshot or per-Agent regression suite.
