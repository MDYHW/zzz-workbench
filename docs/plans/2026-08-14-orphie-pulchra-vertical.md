# Orphie & Magus And Pulchra Vertical Plan

## Outcome

Add Orphie & Magus and Pulchra to the current Party Setup and Result loop with
complete full/non-limited starting setups, exact Aftershock/action projection,
Orphie's Energy-derived capped ATK provider, Pulchra's selected-King lifecycle,
and the new Gilded Blossom, Box Cutter, and Proto Punk equipment identities.

The visible flow must stay within the existing party editor, Setup cards,
candidate descriptions, threshold gauges, Result breakdowns, and action rows.
No new screen or runtime scoring surface is needed.

## Authority and settled contrasts

- Permanent owners: `setup-workbench-product-contract.md`,
  `source-fact-boundary.md`, `zzz-formula-mechanics.md`,
  `zzz-game-vocabulary.md`, and `workbench-ui-design-rules.md`.
- Local owner:
  `docs/brainstorms/2026-08-14-orphie-pulchra-vertical-requirements.md`.
- Closest consumers: Anby: Soldier 0 for Aftershock, Astra/Soukaku/Pan Yinhu
  for capped providers, Soldier 11 for typed NEDF qualification, Corin for
  partial-but-competitive Attack packages, Lycaon/Lighter for selected-King
  pressure, Trigger/Dialyn for independent-CRIT King priority, and current
  Astral/King/Swing/Moonlight allocation and projection.
- Preserved contrasts: equipment-only action modifiers do not become Agent
  relationships; Pulchra's M1 CRIT does not create Trigger-like independent
  CRIT authoring; Proto's legal trigger does not make it a universal Stun first
  choice; candidate dominance does not replace exact Result projection.

## Units

### 1. Static content and authored preparation

- Extend typed Agent, Engine, Disc, faction, source, and formula identities.
- Add current identities and retained values for both Agents.
- Add exact Gilded Blossom, Box Cutter, and Proto Punk facts, compressed Setup
  copy, candidate pools, and assets.
- Add pool-specific representatives, main candidates, base substats, selected-
  King CRIT pressure, and existing allocation participation.
- Cover candidate completeness, exact-identity descriptions, zero-substat
  representatives, full/non-limited differences, King off/on/reselected state,
  and composed Hugo two-Stun King/Astral/Shockstar allocation contrasts in
  shared behavior tests.

### 2. Provider, party qualification, and Result projection

- Add typed NEDF membership and Orphie/Pulchra Additional qualification.
- Add Orphie's Energy-derived Zeroed In ATK with exact complete-step cap,
  Aftershock DMG/DEF Ignore, retained Mindscapes, and exact selected equipment
  scopes.
- Add Pulchra's four-action Daze, M0-M5 Aftershock provider versus default-M6
  broad provider, retained M1/M2, and selected W-Engine/Disc projection.
- Reuse existing formula/action composition and non-stacking recipient phases;
  extend only the smallest shared types needed for Proto's existing Assist
  trigger summary and new source identities.
- Cover the full prepared Orphie/Pulchra flow, pool/Mindscape target rebuilds,
  formula and action contrasts, cap/threshold gauges, and incomplete Result in
  existing shared calculation/state/App test families.

### 3. Portraits and visible verification

- Wire both existing original portrait assets and identity marks.
- Inspect original assets before changing metadata; calibrate fixed scale,
  `headTopY`, then `faceX` for the shared responsive destinations.
- Verify at `127.0.0.1:5173` with both Agents visible: desktop and one narrow
  viewport, expanded and compact states, full/non-limited preparation,
  selected/candidate equipment copy, Pulchra King lifecycle, Result action
  differences, and incomplete-selection behavior.

### 4. Integration, review, and closure

- Run focused tests while implementing, then the full Vitest suite, TypeScript
  build, production build, and `git diff --check`.
- Review permanent-authority fidelity separately from implementation fidelity;
  inspect the final diff for accidental catalogues, duplicated local policy,
  unsupported allocation, and unrelated changes.
- Record one compact completed milestone in `docs/plans/README.md` and remove
  this plan only after a committed revision preserves it.

## Ownership and dependencies

- Controller owns all semantic, candidate, representative, allocation,
  formula/action, lifecycle, portrait-calibration, review, and commit decisions.
- Static facts remain in `src/workbench/content/`; calculation stays in Agent-
  local modules plus existing provider/composition boundaries; shared lifecycle
  stays in candidates/preparation/state rather than named UI conditions.
- Tests extend current mechanism-oriented files. Add no per-Agent suite unless a
  genuinely isolated calculation module needs direct focused coverage.

## Non-goals and stop conditions

- No runtime optimizer, party/Agent registry beyond current typed content,
  rotation/resource/trap simulation, raw damage/Daze, shield Result, evidence
  schema, or UI redesign.
- Stop if implementation exposes an unowned duplicate Astral collision, an
  allocation pairing not settled by the local requirement, a missing source
  fact that changes a visible outcome, a contradiction with a permanent owner,
  or portrait behavior that cannot be calibrated within shared geometry.

## Acceptance gates

- Requirements precede code and every new candidate/representative traces to a
  current consumer and contrast.
- Both pools prepare complete zero-substat setups; Result remains empty for any
  incomplete required selection.
- Selected pressure covers present, absent, and reselected states without
  fallback or history restoration.
- One shared preparation flow composes local representative, King allocation,
  same-effect identity, and party provider behavior in permanent-authority
  order, plus a contrasting unaffected flow.
- New equipment copy and Result projection are verified separately.
- Original portrait assets and all four desktop/narrow expanded/compact
  destinations are visually checked before closure.
